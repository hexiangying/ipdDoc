## 部门

部门是用户的活动区域，所有用户行为必须在某个部门下进行，用户要访问某个部门必须加入到这个部门中来。

一个部门可以理解为是一个部门，比如`研发一部`、`研发二部`为两个独立的部门，也可以是一个开发小组，如：`活动组`、`App服务端组`

在部门下，存在三种角色：部门管理员、开发者、访客，外加一个特殊角色超级管理员，每个角色权限关系如下表所示：

|  角色   | 访问公开项目 | 访问私有项目 | 创建项目   | 编辑部门  | 管理部门成员 |
|  ----  | ----  | ----  | ----  | ----  | ---- |
| 超级管理员  | √  | √ | √ | √ | √ | 
| 部门管理员  | √ | √ | √ |√ | √ | 
| 开发者  | √ | 加入后查看 | √ |  |   |
| 访客  | √ | 加入后查看|  |  |   |

一般来说，部门管理员相当于部门经理，当有新人入职后，部门经理把新人加到部门当中，然后由项目管理员负责把新人拉入到对应的项目中。

### 部门划分参考

假设公司只有一个研发部门，那么可以根据开发小组来划分部门，假如有以下几个开发小组：

- admin组：负责开发admin后台
- BI组：负责开发数据统计
- 活动组：负责开发各种活动项目
- app服务端组：负责开发app服务

**方案1**：划分四个部门，开发小组负责人自行创建对应的部门

- 部门1：admin，项目有：xx管理系统、官网系统
- 部门2：BI，项目有：报表统计系统
- 部门3：活动中心，项目有：活动中心
- 部门4：app服务，项目有：app主程序、小程序服务、微信服务、定时任务系统

当有新人入职，各部门负责人按需求把新人拉入到自己的部门当中，再拉入具体的项目中

在项目数量较多的情况可以选择这种方式

**方案2**：只划分一个部门，部门管理员为部门经理

当项目数量不多的情况下可以只划分一个部门，然后把所有项目放在这个部门下，这样管理起来比较方便

此外，存在多个研发部门的情况下，可以按研发部门划分部门，然后采用方案2来管理

## 项目

进入到部门之后，展示的是部门下的项目，点击项目进入到具体的项目当中。

在项目中也分为三种角色：项目管理员、开发者、访客，外加一个特殊角色超级管理员，每个角色权限关系如下表所示：

|  角色   | 浏览文档 | 编辑项目信息 |  管理模块  | 管理接口 | 管理项目成员   |
|  ----  | ----  | ----  | ----  | ----  | ---- |
| 超级管理员  | √  | √ | √ | √ | √ | 
| 部门管理员 | √ | √  | √ | √ | √ | 
| 开发者 | √ | √  |  √ | √ |
| 访客 | √ |    |  |  |   |
